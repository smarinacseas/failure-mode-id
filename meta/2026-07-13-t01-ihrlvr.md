# T01-ihrlvr, VerIH RLVR on Qwen3-8B: pilot run report

**Date:** 2026-07-13
**Status:** Complete: **null transfer result**; T01 harness run *not* executed (gate decision).
**Spec / plan:** `docs/superpowers/specs/2026-07-12-training-pilot-rlvr-design.md` · `docs/superpowers/plans/2026-07-12-training-pilot-rlvr.md`

## 1. What this pilot tested

Replicate a lab workflow end-to-end at pilot scale: take the failure mode the
analysis flagged (`constraint_overridden`), fine-tune an open model with a
method the literature maps to it (VerIH-style RLVR: reasoning-gated,
verifier-rewarded instruction-hierarchy training), and **measure whether it
transfers** on a held-out benchmark: *before* spending on the full eval
harness. The design gate: train → IHEval gate → **decide**.

## 2. What was built (all landed, reviewed, merged)

- **Harness enablement:** T-series experiment slugs; a `proxy://` per-candidate
  transport so a locally-served fine-tune runs through the untouched eval
  pipeline.
- **Dashboard track separation:** partitioned `runs.json`/`training.json` + an
  Analysis ⟷ Training-pilots view switcher (E-series left byte-identical).
- **`training/` package:** native VerIH verifier reward (`verih_reward.py`,
  faithful to the repo's `ih.py`), VerIH loader (`data.py`), Tinker GRPO loop
  with durable checkpointing + resume (`train_rlvr.py`), OpenAI-compatible
  Tinker proxy (`proxy.py`), IHEval gate (`iheval.py`).
- 280 tests green.

## 3. Training run (Qwen3-8B, Tinker LoRA GRPO)

| Param | Value | vs VerIH published |
| --- | --- | --- |
| base model | `Qwen/Qwen3-8B` | same |
| adapter | LoRA rank 32 | **full fine-tune** |
| steps / epochs | 225 (~1 epoch) | **12 epochs** |
| prompts × group | 32 × 4 | batch 128, rollout 4 |
| max response tokens | 2048 | 2048 |
| lr | 1e-5 | 1e-6 (full-FT) |

Reward = 1.0 iff the response contains a `<think>…</think>` block **and** the
sample's native VerIH verifier is satisfied, else 0.0 (per `ih.py`).

**In-distribution training reward (windowed mean ± sd; format-gated):**

| steps | mean_reward | format_ok |
| --- | --- | --- |
| 0-24 | 0.412 ± 0.080 | 0.940 |
| 25-74 | 0.396 ± 0.075 | 0.945 |
| 75-124 | 0.437 ± 0.081 | 0.952 |
| 125-174 | 0.420 ± 0.073 | 0.955 |
| 175-224 | 0.455 ± 0.076 | 0.965 |

Reward was **noisy and roughly flat with a slight upward drift** (~0.41 → 0.46
across the run; step-to-step sd ≈ 0.08 at group size 4). Format compliance rose
modestly (0.94 → 0.965). The model learned *something* on the training
distribution, but weakly.

## 4. The gate: base vs ft on held-out VerIH test (n=80/split)

| Split | base | ft | Δ | verdict |
| --- | --- | --- | --- | --- |
| **conflict** (headline) | 0.350 (28/80) | 0.362 (29/80) | **+0.0125** | null |
| **aligned** (guardrail) | 0.637 (51/80) | 0.650 (52/80) | +0.0125 | no regression |

Each delta is **+1 example in 80**. Two-proportion test on the conflict split:
**z = 0.17, p ≈ 0.87**; 95% CI on the delta ≈ **±0.148**. The fine-tune produced
**no measurable transfer** to held-out instruction-hierarchy behavior. The one
positive: the aligned split did not regress.

**Power caveat (stated honestly):** n=80 is only powered for a large
(VerIH-sized, ~17-point) effect. A true small-to-moderate transfer could be
masked. But the observed effect is +1 example on a deliberately under-scaled
intervention: the parsimonious reading is *little real transfer from this run*,
not *a real effect hidden by noise*.

## 5. Diagnosis: why null is unsurprising

VerIH's published 46→63 on this exact base model used **full fine-tuning, 12
epochs, batch 128**. This pilot ran **LoRA-32, ~1 epoch, group 4**, on the
order of one-twelfth the training and a far lower-capacity adapter. The flat
in-distribution reward curve is consistent with under-training. This is a
**dosage** result, not evidence the method fails.

## 6. Decision (per the gate protocol)

Gate flat → **T01 Complex-Constraints harness run was NOT executed.** Running it
would have bought a second, costlier measurement of the same null. No
`T01-ihrlvr` entry exists in the Training-pilots dashboard view by design.
**Total spend ≈ $17** (~$15 training, ~$2 gate): the gate saved the harness
cost.

## 7. Infrastructure outcome

The pilot's *engineering* goal succeeded fully. The train → serve → gate →
measure loop works end-to-end and produces trustworthy numbers, and it survived
two real live failures via the hardening built mid-flight:
- **Tinker 402 (billing exhausted) at step 151** of an early run: motivated durable periodic checkpoints + `save_state` resume.
- **Background-task teardown at step 36** of the funded run: recovered via `RESUME=1` from the step-24 checkpoint, losing ~12 steps (visible as the 237 logged steps for a 225-step run).
- A live-only bug (`verih_reward.py` leaking VerIH's `reward_score/` onto `sys.path`, shadowing stdlib `math`) surfaced by the gate and fixed (`5564707`).

## 8. What a powered follow-up needs

To give the method a fair test (a separate, funded experiment: est. +$30 to 60):
- **More epochs** (3 to 5 ≈ 675 to 1125 steps) and/or **higher LoRA rank** (64 to 128).
- **Larger group size** (8 to 16) to cut advantage-estimate variance (the ±0.08 noise floor here).
- **Gate at n≥150/split** to power for a 10-point effect (n=80 was under-powered).
- Only on a gate that clears noise: run the T01 harness for the by-failure-mode base-vs-ft view.
